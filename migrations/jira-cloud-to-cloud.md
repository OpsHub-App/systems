## Overview

After acquisitions, mergers, or organic growth, organizations often end up with multiple Jira Cloud instances. Multiple instances mean fragmented data, duplicated workflows, no cross-project visibility, and higher licensing costs.

OpsHub Migration Manager consolidates multiple Jira Cloud instances into a single instance — preserving all data, history, and relationships — while every team continues working without interruption.

## Why Consolidate with OpsHub?

| Manual Consolidation | With OpsHub Migration Manager |
|---|---|
| Export/import loses revision history | **Complete history** preserved with original timestamps |
| Teams stop work during migration | **Zero downtime** — all instances remain live |
| Project key conflicts require manual resolution | **Automated conflict resolution** for keys, users, and fields |
| Relationships and links break across instances | **Cross-instance relationships** preserved and re-linked |
| Weeks of manual effort per instance | **Parallel migration** of multiple instances simultaneously |

## What Gets Migrated

- All issue types with full field data and revision history
- Comments, worklogs, attachments, and inline images
- Custom fields with type matching
- Workflows, screens, and configurations
- Issue links and epic hierarchies
- Sprint history and board configurations
- User identities mapped and deduplicated
- Filters, dashboards, and saved views

## Use Cases

**Post-Acquisition Consolidation**
Two companies merge, each with their own Jira Cloud. OpsHub migrates both into a single instance, deduplicates users, resolves project key conflicts, and preserves all history.

**Multi-Instance Cleanup**
A growing organization created separate Jira Cloud instances per department. OpsHub consolidates them into one for unified visibility and lower licensing costs.
