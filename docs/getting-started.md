# Getting Started with OpsHub

> Step-by-step guide to your first integration or migration using OpsHub on Atlassian Marketplace.

## For Integration (OIM)

### Step 1 — Install OIM from Atlassian Marketplace

Visit the [OIM listing on Atlassian Marketplace](https://marketplace.atlassian.com/apps/1224525/opshub-integration-manager-oim-for-jira-integrations) and install it to your Jira Cloud instance. For a free version, start with the [OIM Community Edition](https://marketplace.atlassian.com/apps/1215532/opshub-integration-manager-oim-community-edition).

### Step 2 — Connect Your Systems

Use the pre-built connectors to link Jira with your other tools (Azure DevOps, ServiceNow, IBM DOORS, Salesforce, etc.). No global admin access required.

### Step 3 — Configure Field Mappings

Map fields, statuses, and workflows between the two systems using OIM's no-code interface. Define what gets synced, in which direction, and under what conditions.

### Step 4 — Activate and Monitor

Start the integration. OIM synchronizes data bi-directionally in real time. Monitor sync status through built-in dashboards.

**Need help?** [Request a personalized demo](https://www.opshub.com/request-a-demo/) or visit [docs.opshub.com](https://docs.opshub.com) for detailed guides.

## For Migration (OMM)

### Step 1 — Install OMM from Atlassian Marketplace

Visit the [OMM listing on Atlassian Marketplace](https://marketplace.atlassian.com/apps/1224539/omm-for-jira-migration-from-any-tool-with-no-downtime) and install it.

### Step 2 — Run Data Discovery

OMM's Data Discovery Utility scans your source system to analyze project scope, data volume, entity dependencies, and custom field complexity. This produces a migration plan with estimated timelines.

### Step 3 — Configure the Migration

Map entity types, fields, statuses, and workflows between your source system and Jira. Define which projects migrate in which order.

### Step 4 — Run a Pilot

Migrate a representative project first. Validate data accuracy, field mappings, and relationship preservation in Jira. Adjust configuration based on results.

### Step 5 — Execute Full Migration

Run the production migration. Your source system stays live — teams keep working. Delta sync captures ongoing changes. Multiple projects migrate in parallel.

### Step 6 — Validate and Cut Over

Review the reconciliation report. Run a final delta sync. Switch teams to Jira with full confidence.

**Need help?** [Book a free migration consultation](https://www.opshub.com/book-a-free-migration-consultation/) to talk with a migration engineer about your specific scenario.
