# Jira - Azure DevOps Integration

Keep Jira and Azure DevOps teams working in their own tools while sharing the same data. OIM syncs work items, bugs, user stories, epics, comments, and attachments bidirectionally in real time.

---

## The Problem This Solves

After a merger, an acquisition, or a platform split, some teams end up on Jira and others on Azure DevOps. Cross-team work stalls because neither side can see what the other is doing. Leads spend hours in status meetings reconciling spreadsheets.

OIM connects both platforms so every team sees the same, current data in their own tool.

---

## What Syncs

| Data Type | Sync Direction | Details |
|-----------|---------------|---------|
| Work items / Issues | Bidirectional | Bugs, user stories, tasks, epics |
| Comments | Bidirectional | Discussion threads stay aligned |
| Attachments | Bidirectional | Files, images, logs |
| Status / State | Bidirectional | Jira workflows map to Azure DevOps board columns |
| Sprint / Iteration | Bidirectional | Iteration path mapping |
| Custom fields | Bidirectional | Any field to any field |
| Area paths | Configurable | Route items to specific Azure DevOps areas |
| Links and relations | Bidirectional | Parent-child, related, dependencies |

---

## Key Capabilities

- **No-code setup.** Visual configuration for field mapping, value mapping, and workflow transitions
- **Multi-instance.** Connect multiple Jira instances to multiple Azure DevOps organizations
- **Azure DevOps Server and Services.** Works with both cloud (Azure DevOps Services) and on-prem (Azure DevOps Server)
- **Conflict resolution.** Reconciliation engine prevents data loss when both sides update simultaneously
- **External architecture.** No Azure DevOps extensions to install. Connects via REST APIs

---

## Common Use Cases

1. **Post-acquisition tool consolidation.** Acquired team uses Jira, parent company uses Azure DevOps. OIM bridges the gap while teams transition
2. **Vendor collaboration.** External vendor works in Jira; internal teams work in Azure DevOps. OIM keeps shared work items aligned
3. **Gradual platform migration.** Moving from Jira to Azure DevOps (or the reverse) team by team, with sync maintaining continuity during the transition
