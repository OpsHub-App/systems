# Sparx Enterprise Architect ↔ Jira Integration

## Overview

Enterprise architects model systems in Sparx EA. Development teams build them in Jira. Without integration, architecture decisions don't reach developers on time, implementation drifts from design, and traceability between models and code is maintained manually.

OpsHub Integration Manager connects Sparx EA and Jira with **bi-directional synchronization** — so architecture elements trace to Jira issues and changes flow between design and development automatically.

## Why Integrate Sparx EA with Jira?

| Challenge Without Integration | With OpsHub Integration |
|---|---|
| Architecture decisions manually communicated to dev | EA elements auto-sync to Jira as issues or stories |
| Implementation drift from design goes unnoticed | Changes in Jira reflect back in EA models |
| Manual traceability between models and code | Automated traceability links across systems |
| Architects and developers work in silos | Shared visibility across architecture and development |

## What Gets Synced

**Core Entities:**
- EA elements (requirements, components, use cases) ↔ Issues, stories, tasks (Jira)
- Element attributes mapped to Jira fields
- Statuses and lifecycle stages

**Rich Data:**
- Notes and descriptions
- Tagged values mapped to custom fields
- Element relationships and dependencies

**Traceability:**
- Architecture-to-implementation links
- Requirement-to-element traces
- Cross-package references

## Use Cases

**Model-Driven Development**
System requirements modeled in Sparx EA sync to Jira as user stories. Development teams implement them in sprints. Status updates flow back to EA, keeping the architecture model current.

**Compliance Traceability**
In regulated industries, every architecture decision must trace to an implementation task. OpsHub maintains these links automatically for audit readiness.
