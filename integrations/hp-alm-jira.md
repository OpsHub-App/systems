# OpenText ALM (HP ALM) ↔ Jira Integration

## Overview

QA teams working in OpenText ALM (HP ALM) and development teams on Jira need to share defects, requirements, and test results seamlessly. Without integration, bug reports are duplicated, test coverage gaps go unnoticed, and release decisions are made on incomplete data.

OpsHub Integration Manager connects OpenText ALM and Jira with **bi-directional, real-time synchronization** — so defects, requirements, and test data flow automatically between QA and development.

## Why Integrate OpenText ALM with Jira?

| Challenge Without Integration | With OpsHub Integration |
|---|---|
| Defects manually copied between ALM and Jira | Defects auto-sync bi-directionally in real time |
| Test results not visible to developers | Test execution data flows to Jira automatically |
| Requirements changes lost between systems | Requirements sync with full traceability |
| Release decisions based on stale test data | Live test status available across both systems |

## What Gets Synced

**Core Entities:**
- Defects, requirements, and tests (ALM) ↔ Issues, bugs, stories (Jira)
- Priorities, statuses, and workflow transitions
- Assignees and detected-by users

**Rich Data:**
- Comments with original author and timestamps
- Attachments and screenshots
- Custom fields with configurable mappings
- Test steps and expected results

**Test Assets:**
- Test plans and test sets
- Test cases with steps
- Test run results and execution status
- Defect-to-test linkages

## Use Cases

**Defect Synchronization**
QA finds a bug in ALM during test execution. It auto-syncs to Jira for the dev team. When fixed, the status update flows back to ALM — QA knows to re-test without manual follow-up.

**Requirements Traceability**
Requirements in ALM trace to Jira stories. When a requirement changes, linked Jira items are updated automatically, maintaining full traceability for compliance.

**ALM Modernization**
Organizations moving from ALM to Jira use the integration as a bridge — teams can work in their preferred tool while data stays synchronized during the transition.
