# PTC Codebeamer ↔ Jira Integration

## Overview

PTC Codebeamer is an ALM platform built for regulated industries — managing requirements, risks, tests, and change processes in a single tool. When product teams plan in Codebeamer and software teams build in Jira, connecting both systems ensures traceability from requirements through implementation.

OpsHub Integration Manager connects Codebeamer and Jira with **no-code, bi-directional synchronization** — so trackers, work items, and test data flow automatically between both platforms.

## Why Integrate Codebeamer with Jira?

| Challenge Without Integration | With OpsHub Integration |
|---|---|
| Requirements in Codebeamer are manually entered in Jira | Tracker items auto-sync to Jira as stories or bugs |
| Development progress is invisible in Codebeamer | Jira status syncs back to Codebeamer in real time |
| Change management requires manual coordination | Change requests flow between systems automatically |
| Traceability from requirements to code is broken | End-to-end traceability maintained across both tools |
| User fields lose context during manual transfer | User mappings preserved automatically via email or name |

## What Gets Synced

**Core Entities:**
- Requirements, stories, backlog items, tasks, defects, test cases, and execution results (Codebeamer) ↔ Epics, stories, bugs, features, and custom issue types (Jira)
- Custom trackers and custom issue types

**Rich Data:**
- Comments with original author and timestamps
- Attachments, links, and relationships
- User field mappings (assignee, reporter) matched automatically
- Custom fields and field-level mappings

**Relationships:**
- Requirement-to-implementation links
- Test-to-defect traceability
- Parent-child hierarchies

## Use Cases

**Requirements Management**
Systems engineers define requirements in Codebeamer. Requirements auto-sync to Jira as development stories. When developers complete the work, status flows back to Codebeamer — closing the loop on requirements fulfillment.

**Change Management**
A change request is raised in Codebeamer. It syncs to Jira for implementation. As developers update the work item, the change request in Codebeamer reflects current status — no manual status meetings needed.

**Release Management**
Release managers track releases in Codebeamer while development teams manage sprints in Jira. OpsHub keeps both views aligned so release decisions are based on real-time data.
